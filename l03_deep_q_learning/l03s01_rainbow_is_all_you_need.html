De DQN à Rainbow (TP 1 h 15)

Le tutoriel Rainbow is all you need décompose l’algorithme Rainbow en neuf chapitres : chacun part du DQN de base et lui ajoute une seule amélioration, jusqu’à les combiner toutes.

Chaque chapitre est un notebook autonome qui entraîne un agent sur CartPole-v1 (20 000 pas), trace la courbe d’apprentissage et produit une vidéo de la politique apprise. Tout est préinstallé dans le docker du cours : vous n’avez rien à installer.

Note

Ces notebooks sont écrits avec marimo et non avec Jupyter. Un notebook marimo est un fichier .py ordinaire, et il est réactif : quand vous modifiez une cellule, toutes celles qui en dépendent se ré-exécutent automatiquement. Il n’y a donc jamais d’état caché incohérent, mais changer un hyperparamètre relance l’entraînement. Réfléchissez à votre modification avant de la lancer.

Avant de commencer

Récupérer le script de lancement

Ce TP utilise une version du script de lancement qui démarre aussi le serveur de notebooks.

mkdir -p ~/rl/mujoco && cd ~/rl/mujoco && rm -f start.sh && wget -O start.sh https://raw.githubusercontent.com/yguel/docker_mujoco_rl_101/main/start.sh && chmod +x start.sh

Astuce

Ce script remplace celui que vous utilisiez jusqu’ici.

Lancement

cd ~/rl/mujoco && ./start.sh

Le script vérifie l’image, la met à jour si besoin, puis démarre l’environnement. Au bout d’une trentaine de secondes, il affiche :

🌈 Rainbow notebooks ready: http://localhost:2718
   (9 chapters, from DQN to Rainbow)

Vous avez alors trois accès, dans votre propre navigateur :

Adresse

Contenu

http://localhost:2718

Les 9 chapitres du TP (serveur marimo)

http://localhost:6080

Le bureau Ubuntu complet (VS Code, terminal, MuJoCo)

http://localhost:8888

Jupyter, pour les notebooks des séances précédentes

Pour ce TP, travaillez sur http://localhost:2718.

Note

Depuis le bureau (http://localhost:6080) vous retrouvez aussi une icône Rainbow Notebooks et la commande start-rainbow.sh dans un terminal. C’est le même serveur : utilisez ce qui vous arrange.

Quand vous avez fini votre session de travail, fermez le docker proprement avec CTRL+C dans le terminal où le script a été lancé.

Vos fichiers

Au premier lancement, les neuf chapitres sont recopiés dans ~/workspace/rainbow-is-all-you-need/ (côté conteneur), c’est-à-dire dans votre workspace persistant. C’est cette copie que vous modifiez et elle survit à l’arrêt du docker.

L’original reste intact dans /opt/rainbow-is-all-you-need/. Si vous cassez un notebook :

cp /opt/rainbow-is-all-you-need/01_dqn.py ~/workspace/rainbow-is-all-you-need/

Déroulé de la séance

Vous n’aurez pas le temps de traiter les neuf chapitres en profondeur en 1 h 15. Le but est de maîtriser le squelette (ch. 01), de comprendre comment on y greffe une amélioration (ch. 02), puis de voir ce que donne l’assemblage complet (ch. 08). Les autres chapitres sont à faire chez vous.

Le calcul de fond

Dès le début de la séance, ouvrez un terminal sur le bureau (http://localhost:6080) et lancez :

cd ~/workspace/rainbow-is-all-you-need
for f in 0*.py; do echo "=== $f ==="; python3 "$f"; done

Les notebooks marimo étant de simples fichiers .py, ils s’exécutent directement. En une dizaine de minutes vous obtiendrez les vidéos et les courbes des neuf agents dans videos/, que vous pourrez comparer en fin de séance sans rien attendre.

Questions à rendre

Déposez sur Moodle un fichier texte ou PDF avec vos réponses, quelques lignes chacune.

Chapitre 01 — DQN

  1. Q1. Dans la classe DQNAgent, deux réseaux coexistent : dqn et dqn_target. Repérez où dqn_target est mis à jour. Que se passerait-il si on le mettait à jour à chaque pas plutôt que tous les target_update pas ?

  2. Q2. epsilon_decay = 1 / 2000 avec num_frames = 20000. À partir de quel pas l’agent est-il essentiellement glouton ? Que voyez-vous sur la courbe à ce moment-là ?

  3. Q3. Le score maximal atteignable est 200 (max_episode_steps=200). Votre agent l’atteint-il ? Est-il stable à 200 ou retombe-t-il ?

Chapitre 02 — Double DQN

  1. Q4. Comparez la méthode _compute_dqn_loss des chapitres 01 et 02. Écrivez les deux formules de la cible. En quoi la seconde corrige-t-elle le biais d’optimisme ?

  2. Q5. Sur CartPole, l’écart entre DQN et Double DQN est faible. Pourquoi ? Dans quel type d’environnement l’écart deviendrait-il important ?

Chapitre 08 — Rainbow

  1. Q6. Rainbow combine six améliorations. Lesquelles reconnaissez-vous dans le code ? Citez pour chacune la classe ou la ligne qui l’implémente.

  2. Q7. NoisyNet remplace l’exploration \(\varepsilon\)-greedy. Trouvez dans le code du chapitre 08 la preuve que epsilon a bien disparu de la boucle de décision.

Synthèse

  1. Q8. À partir des courbes des neuf chapitres, classez les améliorations de la plus utile à la moins utile sur CartPole. Cette conclusion est-elle transposable aux jeux Atari du papier Rainbow ? Justifiez en une ou deux phrases.

Pour aller plus loin

  • Les chapitres 03 à 07, un par un : chacun isole une seule brique de Rainbow.

  • Le chapitre 09 : Rainbow + IQN, la version distributionnelle la plus aboutie.

  • Faites varier num_frames, memory_size et batch_size dans le chapitre 01 et observez l’effet sur la courbe d’apprentissage.

Dépannage

http://localhost:2718 ne répond pas

Le serveur met quelques secondes à démarrer : attendez l’affichage de 🌈 Rainbow notebooks ready dans le terminal, puis rechargez la page.

S’il ne vient pas, ouvrez un terminal sur le bureau (http://localhost:6080) et lancez start-rainbow.sh : vous verrez le message d’erreur. Le journal est dans ~/marimo.log.

« Rainbow notebooks are not available in this image »

Votre image docker est antérieure au tutoriel. Faites CTRL+C puis relancez ./start.sh : il téléchargera la mise à jour (environ 60 Mo).

« workspace is not writable »

Vos notebooks sont alors dans ~/rainbow-is-all-you-need et seront perdus à l’arrêt du conteneur. Prévenez l’enseignant et sauvegardez vos réponses ailleurs en attendant.
